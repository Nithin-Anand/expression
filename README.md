# 📸 Minimally Processed

> *A personal photography portfolio & blog by Nithin Anand*

---

## ✨ Welcome!

**Minimally Processed** is a clean, modern, Astro-powered site to showcase my favourite images, share photo stories, and blog about my journey as an amateur photographer. I'm making the source code available here so that you can fork it. Images are now served via Cloudinary CDN for better performance. I have made this repo open-source in good faith, please do not use the content (blogs and photos) without permission. 

---

## 🚀 Features & Recent Updates

- **CDN Integration**: Images are dynamically fetched and optimized using Cloudinary.
- **Lightbox**: Implemented a custom lightbox for viewing images in full detail.
- **Responsive Gallery**: Improved grid layout that adapts seamlessly to different screen sizes.
- **Photo Essays**: Album pages support optional long-form introductions and per-image captions from Cloudinary context metadata.
- **SEO Optimized**: Enhanced metadata and structure for better search engine visibility.

### Writing an album essay

Add an optional YAML block to any file in `src/content/albums`:

```yaml
essay: |
  The first paragraph introduces the place, people, or idea behind the album.

  Blank lines create new paragraphs, so longer stories remain easy to edit.
```

Album images are sequenced automatically by their Cloudinary public ID. To add a caption without maintaining another image list, set the image's `caption` (or `alt`) context field in Cloudinary.

## Local development

Use Node 22.23.4 or newer (`nvm use` selects the supported Node 22 release), then:

```sh
npm ci
cp .env.example .env
# Fill in your Cloudinary credentials in .env.
npm run dev
```

Cloudinary API credentials are used only during server-side rendering and builds. They must also be configured in Cloudflare Pages. There is no Python setup or separate stats scraper: the site reads one validated, paginated photo catalog per build process (refreshed every minute in the dev server), and derives galleries and statistics from that same catalog. Missing credentials, failed API requests, and invalid image data stop publication. Failed fetches are evicted from the cache so the next development request can retry.

```sh
npm run check       # Astro and TypeScript diagnostics; no credentials needed
npm run format:check # Consistent source formatting (npm run format to apply)
npm test            # Offline data, pagination, URL and timezone regressions
npm run build       # Type check and production build; Cloudinary credentials required
npm run test:build  # Inspect the generated site for drafts, broken links and regressions
npm run test:fixture # Build synthetic metadata and check routes without credentials
npm run verify      # Run the complete local validation sequence
```

CI runs formatting, type checking, unit tests, and a complete fixture-based build on pushes and pull requests. The fixture config uses synthetic photo metadata without API credentials, and writes to `dist-fixture/` so it cannot overwrite the production build in `dist/`. Normal builds compile fixture loading out. Cloudflare runs the production build with its configured secrets. `dist/stats.json` is generated by an Astro endpoint; it is no longer a separate input in `public/`.

## Code organisation

```text
src/
  assets/                  Local images and logos
  components/              Shared rendering (SEO, navigation, page container, image)
    gallery/               Photo grid and lightbox markup
    stats/                 Charts and recently added photos
  content/                 Album YAML and blog Markdown
  content.config.ts        Astro collection schemas and loaders
  data/                    Server-side Cloudinary catalog and content queries
  layouts/                 Site shell and blog article layout
  lib/                     Date formatting, image URLs and pure stats calculations
  pages/                   Routes: select data and compose layouts/components
  scripts/                 Browser interactions: lightbox and Chart.js
  styles/                  Global Tailwind configuration
scripts/                   Node build-test orchestration
astro.config.fixture.mjs   Explicit CI-only build configuration
tests/
  fixtures/                Synthetic Cloudinary metadata
  *.test.ts                Offline logic regressions
  build/                   Checks against production output
```

Page templates compose data and markup. API parsing, pagination and error handling belong in `data/photos.ts`; browser code never imports that module at runtime. Stats are calculated once in `lib/stats.ts`, without browser-time gap filling or local-time date arithmetic. Publication rules and post ordering are shared in `data/content.ts`, so a draft cannot gain a public route just because it is absent from the index.

`PageContainer` owns responsive spacing and reading widths. `BaseLayout` owns page metadata, navigation and the main landmark; `BlogPostLayout` owns article metadata and typography. `PhotoGrid` owns thumbnails, captions and accessible lightbox triggers; `CloudinaryImage` owns responsive image markup. Keep page-specific content in routes rather than adding a component for every short section.

## AI crawling

The crawler policy requests that named AI training, search and fetch bots stay out while allowing ordinary search engines. It is not an access-control mechanism. Live Cloudflare enforcement, media-host limits, and verification are covered in [docs/crawling.md](docs/crawling.md).

## Content conventions

- Album IDs match YAML filenames, including underscores, so existing URLs and Cloudinary folder names remain stable. Add corresponding synthetic metadata in `tests/fixtures/photos.json` when introducing a new album so CI can render it.
- Album photos come from the corresponding `albums/<id>` asset folder. The portfolio uses the `portfolio` tag. Photos have a stable order by public ID.
- Set `showDate: false` for evergreen collections. The portfolio's legacy sorting date is never displayed.
- Blog covers are optional; coverless posts render as text cards. `draft: true` excludes a post from both the index and static routes.
- Captions use Cloudinary's `caption`, falling back to `alt`. Essay paragraphs are separated by blank lines and rendered as text.
